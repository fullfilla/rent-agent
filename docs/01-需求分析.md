# 01-需求分析

## 产品一句话定义

租房 Agent 是一个本地可运行的 AI 租房助手，通过对话理解租房需求，结合筛选条件、房源风险规则和定时刷新机制，帮助用户持续发现、比较并筛掉不合适房源。

## 目标用户

- 初次在一线或新一线城市租房的毕业生、转岗人群、异地工作者。
- 对租房平台信息过载、虚假房源、中介话术和合同风险不熟悉的用户。
- 希望用自然语言表达需求，而不是反复手动调筛选器的用户。

## 使用场景

- 用户刚开始租房，只知道预算、通勤区域、户型和偏好，希望 Agent 给出第一批候选房源。
- 用户看过几套房后发现需求变化，例如希望更近地铁、不要隔断、降低预算，需要继续对话调整。
- 用户自己浏览房源列表时，希望系统提示押金、转租、隔断、采光、楼层、通勤等风险。
- 用户希望房源定时刷新，并看到新增或风险变化。
- 用户有自己的大模型 API 服务，希望填写 API Key、Base URL 和模型名称进行替换。

## 核心痛点

- 筛选维度多，用户很难一次把预算、区域、通勤、地铁、朝向、楼层、合租方式、宠物、押金等条件设完整。
- 平台房源描述标准不统一，风险信息隐藏在标题、备注、图片或经纪人话术中。
- 房源变化快，用户需要反复刷新，容易错过新房或重复查看旧房。
- 租房坑多，初学者不知道“押一付三”“服务费”“转租”“隔断间”“民水民电”“无独卫”等信息意味着什么。
- 不同平台是否提供官方租房 API 不稳定，直接依赖单一平台会增加合规和稳定性风险。

## 当前替代方案

- 贝壳、安居客、自如、链家等平台的筛选器和收藏功能。
- 小红书、微信群、豆瓣租房小组等非结构化信息源。
- 手动把房源链接发给 ChatGPT 或其他 AI 让其分析。
- 表格记录候选房源、人工比较价格和通勤。

## 产品核心价值

- 用对话收集需求，降低复杂筛选器的使用门槛。
- 把房源结构化为可比较对象，给出匹配分、风险提示和下一步建议。
- 在用户后续对话中持续调整偏好，而不是每次重新开始搜索。
- 将第三方模型供应商配置开放给用户，便于替换 OpenAI 兼容服务。
- 用可替换数据源适配器承接未来真实平台 API、企业数据服务或用户自定义数据源。

## 关键假设

- MVP 先做本地项目，不部署线上服务。
- 未接入贝壳、安居客真实官方 API；公开可验证信息不足以确认它们提供面向个人开发者的通用租房列表 API。
- MVP 使用 mock 房源数据和 mock agent，代码中保留可替换的模型调用与房源数据适配位置。
- 用户的 API Key 仅保存在浏览器 localStorage 中，用于本地演示，不上传服务器。
- 第一版重点验证“对话调整需求 + 筛选 + 风险提示 + 定时刷新模拟”的核心闭环。

## 第一版成功标准

- 用户能在本地浏览器打开应用。
- 用户能通过对话输入租房需求，系统能提取预算、区域、通勤、户型等条件并推荐房源。
- 用户能手动调整类似贝壳的筛选条件，房源列表随条件变化。
- 每个房源能展示匹配理由、风险标签和需要追问房东/中介的问题。
- 用户能保存第三方 AI 配置：API Key、Base URL、模型名称。
- 页面有定时刷新提示和手动刷新按钮，刷新后能看到 mock 新房源或更新时间变化。
- 应用在桌面和移动宽度下可用。
