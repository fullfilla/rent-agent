# 04-技术设计

## 技术栈选择

- Vite：本地开发服务器，启动快，适合 MVP。
- React：构建单页交互界面。
- TypeScript：为房源、筛选条件、模型配置提供类型约束。
- CSS：使用原生 CSS 变量和响应式布局，不引入重 UI 框架，降低依赖复杂度。
- localStorage：保存筛选条件、对话历史、收藏和模型配置。

## 数据存储方式

- 本地浏览器 localStorage 存储：
  - `rent-agent.criteria`：筛选条件。
  - `rent-agent.messages`：对话历史。
  - `rent-agent.model-config`：第三方模型配置。
  - `rent-agent.favorites`：收藏房源 ID。
- mock 房源数据保存在 `src/data/mockListings.ts`。
- MVP 不写入后端数据库。

## API 或 agent 调用方式

MVP 使用 `src/lib/agent.ts` 中的 mock agent：

- `runMockAgent(message, criteria, listings)`：解析用户文本、更新筛选条件、生成回复和执行步骤。
- 真实模型替换位置：
  - 新增 `runLlmAgent(config, message, criteria, listings)`。
  - 使用用户保存的 `baseUrl`、`apiKey`、`modelName` 调用 OpenAI 兼容接口。
  - 返回结构保持与 mock agent 一致，避免 UI 改动。

房源数据源替换位置：

- 当前：`mockListings` 静态数组。
- 后续：新增 `ListingProvider` 接口，例如 `fetchListings(criteria)`。
- 平台 API：如贝壳/安居客存在正式授权接口，应通过官方协议、账号授权和服务条款接入。
- 非官方页面抓取不作为 MVP 默认方案，避免合规和稳定性问题。

## 状态管理方式

- 使用 React `useState` 管理页面状态。
- 使用 `useMemo` 计算筛选和排序结果。
- 使用 `useEffect` 同步 localStorage 和自动刷新计时器。
- 不引入 Redux/Zustand，避免 MVP 过度复杂。

## 错误处理策略

- 用户输入为空：阻止发送并展示轻量提示。
- localStorage 写入失败：保留内存状态并展示提示。
- 模型配置不完整：允许保存草稿，但明确真实调用需要补全。
- 房源无结果：展示可操作的放宽筛选建议。
- 未来真实 API 失败：保留上次成功结果，展示错误来源、状态码和重试按钮。

- 加入地图、通勤 API、地铁线路和步行距离计算。

- 增加云端账号、跨设备同步和团队共享。
