# 03-交互设计

## 每个页面的布局说明

MVP 采用单页应用。

- 顶部栏固定在页面上方，展示产品名、当前刷新状态、手动刷新、导出 JSON。
- 左侧栏是控制台，包含筛选器、自动刷新开关、模型配置和收藏房源。
- 中间是 Agent 对话区，视觉上接近 Codex 的工作台：消息流、执行步骤、底部输入框。
- 右侧是房源结果区，展示匹配房源列表和每套房的风险提示。
- 移动端改为上下布局：顶部栏、对话区、筛选区、房源区依次排列，避免横向滚动。

## 用户点击后的行为

- 点击“发送”：用户消息进入对话，Agent 解析需求，更新筛选器并刷新结果。
- 点击推荐问题：将示例需求填入输入框或直接发送。
- 点击筛选控件：立即更新结果数量和排序。
- 点击房源“收藏”：加入左侧收藏列表，再次点击取消收藏。
- 点击“复制摘要”：复制当前推荐房源的简短对比文本。
- 点击“导出 JSON”：下载当前筛选条件、模型配置摘要和结果列表。
- 点击“手动刷新”：模拟拉取房源，更新时间并可能插入一条新房源。
- 开启“自动刷新”：每 30 秒执行一次模拟刷新。
- 点击“保存模型配置”：把 Base URL、模型名称和 API Key 保存到 localStorage。

## 加载状态

- Agent 处理时，发送按钮进入 loading 状态，消息区显示“正在理解需求 / 刷新房源 / 检查风险”步骤。
- 房源刷新时，顶部栏显示“刷新中”，房源卡片保留原内容，不用全屏遮挡。
- 保存模型配置时，按钮短暂显示“保存中”。

## 空状态

- 对话为空时，显示 3 个可点击需求示例。
- 房源列表无结果时，展示原因提示：预算过低、区域过窄、风险过滤过严，并提供“放宽预算 / 放宽区域 / 允许中风险”的建议按钮。
- 收藏为空时，提示“收藏后会在这里形成看房清单”。

## 错误状态

- 输入为空时，不发送，提示“先说说预算、区域或通勤要求”。
- 模型配置缺少 Base URL 或模型名称时，提示“配置已保存为草稿，但真实调用前还需要补全”。
- 导出失败时，提示用户可使用复制摘要作为替代。
- 真实 API 未接入时，不显示失败；文案明确为“当前使用 mock agent”。

## 成功状态

- 发送成功后，Agent 回复包含更新了哪些条件、推荐几套房、重点风险。
- 保存模型配置成功后，显示“已保存到本机浏览器”。
- 刷新成功后，显示最新刷新时间和新增房源数量。
- 复制成功后，按钮短暂显示“已复制”。

## Agent 执行过程展示

Agent 每次响应展示 4 步：

1. 解析需求：展示识别到的预算、区域、户型、租住方式。
2. 更新筛选：展示被改变的筛选字段。
3. 匹配排序：展示候选房源数量和排序依据。
4. 风险检查：展示高频风险标签和建议用户追问的问题。

## 结果编辑、复制、导出交互

- 结果编辑：MVP 不支持直接编辑房源字段，但支持通过筛选和对话改变结果。
- 复制：复制当前 Top 3 房源的标题、租金、区域、匹配分、风险标签和推荐理由。
- 导出：导出 JSON 文件，包含筛选条件、刷新时间、收藏 ID、模型配置摘要和当前结果。
